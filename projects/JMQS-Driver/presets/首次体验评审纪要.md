# Persona Driver · 首次体验评审纪要预设

> 日期：2026-08-19
> 范围：localhost Persona Driver → YouNavi conversation 的首次真实闭环。

## 评审目标

验证一次启动是否能完成：选人物 → 选指令 → 确认输入 → 变身反馈 → 创建 Navi 对话 → 激活 Skill → 返回可追踪状态。

## 实际结果

### 已通过

1. `Donald John Trump + ACTION` 成功生成独立 Run。
2. YouNavi 创建 task 与 conversation，source 为 `persona-driver`。
3. conversation 首条用户消息包含 `/trump-perspective`、ACTION、当前任务、输入和输出合同。
4. conversation 出现 `skill_activate` checkpoint，证明显式 Skill 路由成功。
5. 页面能从“正在创建”进入“已入队”，并显示 conversation ID。
6. 检查结果能把 YouNavi 的错误状态回传到角色实例面板。

### 未通过

1. 首次测试的最终角色回复失败，YouNavi 返回 `LLM API 错误: HTTP 400`。
2. 旧输入只有演示文件名，Skill 尝试扩大目录搜索；这不是允许的行为。
3. 当前只能打开 YouNavi 应用，不能从外部精确跳到目标 conversation。

## 本轮决定

- 四项演示输入改成真实、只读 Markdown 预设，Bridge 传入绝对路径和 SHA-256。
- Prompt 明确“只读列出的路径；缺失就报错；禁止 find、遍历 `/Users` 或扩大搜索范围”。
- 页面继续保留模拟角色输出，但必须同时显示真实 Navi 状态，二者不能混为一谈。
- 模型 HTTP 400 单独排查，不通过静默换模型或隐藏错误解决。

## 验收标准

- 新 conversation 不再搜索 `/Users` 或用户主目录。
- 每个输入都能在 request.json 中追溯到绝对路径和 SHA-256。
- Skill 激活、task ID、conversation ID 三者一致。
- 输入缺失时 Bridge 在调用 agent-cli 前失败。
- 公开 Sites 不包含预设绝对路径，也不请求本机 Bridge。
