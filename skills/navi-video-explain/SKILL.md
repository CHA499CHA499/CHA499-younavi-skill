## 固定路径

先设定路径，后续转写和截图都使用这两个命令路径：

```bash
AGENT_CLI=/Applications/YouNavi.app/Contents/Resources/backend/agent-cli
FFMPEG=/Applications/YouNavi.app/Contents/Resources/bin/ffmpeg
```

转写执行：

```bash
"$AGENT_CLI" -f json audio transcribe "<video_file>"
```

失败策略：原样报告错误并停下；不要换成本地转写模型兜底。

## 处理原则

### 1. 先拿到本地视频文件

- 本地路径存在：直接使用。
- URL：先按页面和链接形态获取本地媒体文件；普通下载不可行且确实是平台视频时，再考虑 `yt-dlp`。
- 缺少 `yt-dlp`：如果本机有 `you-get`，可先用 `you-get`；否则说明原因，让用户确认安装或改为提供本地文件。
- 隐私：不要使用 `--cookies-from-browser`，也不要触发浏览器 cookie / 钥匙串 / 登录态读取。使用 `yt-dlp` 时带 `--ignore-config`。

B 站下载失败时：
- `yt-dlp` 返回 HTTP 412 不等于“需要浏览器登录态”。先尝试 `you-get`（如果本机可用）。
- 不要把升级/重装下载器当作默认排障步骤；除非用户明确要求，不执行 `yt-dlp -U`、`pip install -U yt-dlp`、`brew upgrade yt-dlp`。
- 若 `yt-dlp` / `you-get` 都失败，停止并报告错误；不要继续尝试浏览器 cookie、登录态、钥匙串或下载器升级。

```bash
yt-dlp --ignore-config -f "bv*[ext=mp4]+ba/b" --merge-output-format mp4 -o "<workdir>/video.%(ext)s" "<url>"
you-get -o "<workdir>/" "<url>"
```

### 2. 直接转写视频文件

执行上面的转写命令，读取返回的 `data.text`。它通常是带时间戳的逐句文字稿：

```text
[MM:SS - MM:SS] 说话人: 文本
```

如果转写为空或视频无语音，进入「无语音兜底」。

### 3. 提炼要点并选择截图时间点

按视频叙述顺序提炼 5 到 10 个核心要点。每个要点选择一个代表性时间点：

- 优先取该要点讲述区间的中段。
- 避开开头寒暄、过渡句、片头片尾。
- 如果没有稳定时间戳，就根据内容位置估算，并在结果里标明是估算。

### 4. 少量截取关键帧

每个要点最多生成 1 张最终配图。为避开转场或翻页瞬间，可围绕时间点截 3 张候选图：

```bash
"$FFMPEG" -ss <t-2> -i "<video_file>" -frames:v 1 -q:v 2 "<workdir>/p01-a.jpg"
"$FFMPEG" -ss <t>   -i "<video_file>" -frames:v 1 -q:v 2 "<workdir>/p01-b.jpg"
"$FFMPEG" -ss <t+2> -i "<video_file>" -frames:v 1 -q:v 2 "<workdir>/p01-c.jpg"
```

逐组选择最清晰、信息量最大的画面，最终配图不超过 10 张。

铁律：最终输出必须图文并茂。只要视频画面能被截取，就必须在「图文拆解」里插入关键截图；不要因为判断“用户可能只需要文字”而省略图片。只有视频无法取得画面、ffmpeg 截图失败或用户明确要求纯文字时，才允许纯文字输出，并说明原因。

无语音兜底：

- 每 30 秒均匀采样一帧，最多 10 张候选图。
- 看图后挑最多 5 张信息量大的画面，写成纯视觉讲解。

### 5. 直接输出图文讲解

直接在当前对话输出 Markdown。先给一句能帮用户抓住价值的总结或金句，再进入图文拆解；结尾轻量连接到用户当前上下文，不默认展开成长建议。

使用 memory 时遵守两点：

- 只使用当前会话、可用用户记忆和最近上下文；不要编造用户背景。
- 默认只做 2 到 4 句轻量关联。更深入的个人建议、优化点和联想，放到末尾追问后再展开。

```markdown
# <视频标题> · 图文讲解

> 来源：<URL 或文件名> · 生成于 <日期>

## 先说结论

<用 2 到 4 句说明这个视频最重要的观点、判断或启发。>

> <可选：提炼一句金句/判断句。要求短、有辨识度，不要鸡汤。>

## 图文拆解

### 1. <要点标题>（<MM:SS>）

![要点1](<截图本地绝对路径>)

<2 到 4 句讲解：这个片段讲了什么，画面里能看到什么，为什么重要。>

## 和你有什么关系

<结合当前会话 / 可用 memory，用 2 到 4 句说明这个视频和用户正在做的事、长期偏好或当前目标有什么关系。没有足够信息时，明确写“基于当前上下文”。>

## 还可以继续展开

需不需要我结合你的个人 memory，给你提供一些建议，或者展开一些联想？
```

若视频信息密度很高，可增加「关键反常识」「值得复看的位置」两个小节；若视频偏教程/操作流，可在追问前增加「下一步执行清单」。

图片路径使用最终选中截图的本地绝对路径，确保当前对话可以渲染。落选截图可以清理；最终用于展示的截图不要在回复前删除。
